# 개인 반복 일정 애그리거트

도메인 용어는 [glossary.md](glossary.md)를 따른다.

## Root와 Child Entity

- `RecurrenceEvent`는 개인 반복 일정의 Aggregate Root다.
- `RecurrenceEventOverride`는 Root가 소유하는 Child Entity다. Root의 목록에 포함되며 외부에 독립적인 변경 진입점을 제공하지 않는다.
- Root 내부에서 자식을 식별하는 기준은 `originStartAt`이다. 외부에서 회차를 구분할 때는 시리즈 ID와 원래 시작값을 함께 사용한다.
- `overrideId`는 DB 행을 식별하는 키다. API의 회차 식별과 작업 대상 확인에는 사용하지 않는다.
- 같은 원래 시작값의 수정·제외·복원은 같은 자식의 상태 전이다. 시리즈 정의가 바뀌어도 기존 개별 변경은 보존한다.

Root가 목록과 생명주기를 소유하고, 자식은 제목·시간·제외 상태를 관리한다. 생성과 상태 변경은 Root의 행위를 통해 수행하며 자식의 변경 메서드는 패키지 내부로 제한한다. 저장·삭제는 Root의 cascade와 orphan removal을 따르고, 자식 repository는 조회만 제공한다.

## 작업 대상 확인과 상태 변경

사용자가 지정한 회차를 수정·제외할 때는 `requireOccurrence`로 작업 대상을 확인한다. 보존된 개별 변경이 있거나 현재 반복 정의에서 생성되는 회차여야 한다. 반복 계산은 `RecurrenceOriginMatcher` 계약으로 수행한다.

외부 상태를 수신할 때는 동기화 경계에서 부모 시리즈, 원래 시작값, 외부 매핑과 변경 내용의 유효성을 확인한다. 로컬 시리즈 정의가 늦게 도착할 수 있으므로 수신한 회차의 존재를 현재 로컬 규칙만으로 다시 판단하지 않는다.

확인된 회차의 상태는 모두 Root의 `changeOccurrence`와 `excludeOccurrence`로 반영한다. Root의 변경 메서드는 외부 제공자의 종류나 호출 출처를 인자로 받지 않는다.

Root가 항상 지키는 조건은 자식의 소속, 원래 시작값의 유일성, 유효한 변경 내용과 자식 생명주기다. 모든 개별 변경이 항상 현재 반복 규칙에서 생성되어야 한다는 조건은 두지 않는다.
