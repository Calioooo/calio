# 개인 반복 일정 애그리거트

도메인 용어는 [glossary.md](glossary.md)를 따른다.

## Root와 회차 변경 값

- `RecurrenceEvent`는 개인 반복 일정의 Aggregate Root다.
- `RecurrenceEventOverride`는 특정 회차에 적용할 변경 내용 또는 제외 상태를 표현하는 불변 Value Object다.
- Root는 원래 시작값별 변경 값을 소유한다. 외부에서 회차를 지정하는 기준은 시리즈 ID와 `originStartAt`의 조합이다.
- `originStartAt`은 변경이 적용되는 회차를 지정하며 override 객체의 독립적인 identity를 의미하지 않는다.
- 동일한 회차를 수정·제외·복원할 때 Root가 값을 교체한다. 이전 값은 변하지 않으며 값의 동등성은 원래 시작값과 전체 변경 내용으로 판단한다.
- 시리즈 정의가 바뀌어도 기존 개별 변경을 보존한다. 시리즈를 삭제하면 소유한 변경 값도 함께 삭제한다.

변경과 저장은 Root를 통해 수행한다. 저장은 `@ElementCollection`으로 매핑하며 override는 부모 객체 참조, 숫자 ID, 독립적인 Repository를 갖지 않는다. DB 행은 시리즈 ID와 원래 시작값의 조합으로 구분한다.

## 작업 대상 확인과 상태 변경

사용자가 지정한 회차를 수정·제외할 때는 `requireOccurrence`로 작업 대상을 확인한다. 보존된 개별 변경이 있거나 현재 반복 정의에서 생성되는 회차여야 한다. 반복 계산은 `RecurrenceOriginMatcher` 계약으로 수행한다.

외부 상태를 수신할 때는 동기화 경계에서 부모 시리즈, 원래 시작값, 외부 매핑과 변경 내용의 유효성을 확인한다. 로컬 시리즈 정의가 늦게 도착할 수 있으므로 수신한 회차의 존재를 현재 로컬 규칙만으로 다시 판단하지 않는다.

확인된 회차의 상태는 모두 Root의 `changeOccurrence`와 `excludeOccurrence`로 반영한다. Root의 변경 메서드는 외부 제공자의 종류나 호출 출처를 인자로 받지 않는다.

Root가 항상 지키는 조건은 원래 시작값별 변경 값의 유일성, 유효한 변경 내용과 시리즈에 종속된 생명주기다. 모든 개별 변경이 항상 현재 반복 규칙에서 생성되어야 한다는 조건은 두지 않는다.

## 조회와 동기화 식별

필요한 원래 시작값 또는 변경 시간 구간으로 조회하는 쿼리는 Root Repository에 둔다. 변경 시간 구간 조회에서는 변경 값과 시리즈를 함께 반환해 응답·알림·빈 시간 계산에 사용한다. 조회 결과는 별도의 변경 진입점이 아니다.

Google의 외부 일정 ID, ETag와 동기화 상태는 연동 매핑 모델이 소유한다. 매핑은 시리즈와 원래 시작값을 참조하며 override VO의 영속 객체 identity에 의존하지 않는다.

## 로딩과 마이그레이션

회차 변경은 Root를 잠근 뒤 저장된 override 목록을 로딩하고 값을 교체한다. 앱 요청과 동기화·정리 경로는 같은 Root 잠금을 사용해 서로 다른 회차의 변경이 덮어써지지 않도록 한다. 목록 크기와 collection 저장 비용은 별도로 관찰한다.

V43은 기존 회차 변경 데이터를 보존하면서 override 숫자 ID와 독립 감사 시각을 제거한다. 공개 회차 응답의 createdAt·updatedAt은 기존과 같이 시리즈의 값을 사용한다.
