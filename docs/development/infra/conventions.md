# 인프라 구현 컨벤션

## 목적

이 문서는 인프라 설정, CI/CD와 운영 환경 변경의 공통 원칙을 정하는 팀 검토용 초안이다.
특정 서버, 서비스 목록과 리소스 이름을 고정하지 않는다.

## 1. 설정 구성

- 서비스 실행 설정, 배포 절차와 관측 설정을 역할에 맞는 파일에서 관리한다.
- 환경에 따라 달라지는 값은 환경 변수나 설정으로 전달하고, 여러 파일에 반복해서 고정하지 않는다.
- 서비스 간 주소, 포트, 설정 경로와 환경 변수 이름은 사용하는 코드 및 배포 설정과 일치시킨다.
- 같은 의미의 반복 설정만 공통화하고, 환경이나 서비스별로 다른 책임은 분리한다.
- 설정 파일의 위치를 변경하면 배포 복사 경로와 컨테이너 마운트 경로도 함께 확인한다.

## 2. 환경 변수와 비밀값

- 실제 비밀값은 저장소, 이미지와 빌드 산출물에 포함하지 않고 실행 환경의 안전한 경계에서 주입한다.
- 배포에 필요한 환경 설정과 비밀값의 주입 경로를 명확히 관리한다.
- 필수 비밀값이 없을 때 임의의 기본값으로 운영을 시작하지 않는다.
- 운영 설정 검증 시 비밀값이 포함된 환경 변수나 렌더링된 설정을 로그에 출력하지 않는다.
- CI 검증용 설정과 운영 설정을 구분하고, 예제 파일로 서버의 실제 설정을 덮어쓰지 않는다.
- 비밀값의 이름, 저장 위치나 암호화 키를 변경하면 기존 데이터와 실행 환경에 미치는 영향을 먼저 확인한다.

## 3. 컨테이너와 접근 범위

- 외부 공개가 필요한 서비스만 포트를 노출하고, 내부 통신은 내부 네트워크를 사용한다.
- 관리 화면과 관측 서비스의 외부 접근은 인증과 공개 경계를 확인한 후 허용한다.
- 컨테이너 권한과 호스트 마운트는 필요한 범위로 제한하고, 변경이 필요 없는 설정은 읽기 전용으로 마운트한다.
- 데이터베이스와 유지가 필요한 운영 데이터는 컨테이너 교체와 분리된 영속 저장소에 보관한다.
- 서비스 시작 순서와 실제 준비 완료를 구분하고, 필요한 의존 서비스의 상태를 확인한다.
- 외부 이미지 버전 변경은 호환성과 설정 변경을 확인한다. 버전 고정은 업데이트 검토를 생략하는 근거로 사용하지 않는다.

## 4. CI/CD와 배포

- CI/CD 실행 조건, 권한과 비밀값 전달은 필요한 대상과 범위로 제한한다.
- 배포 버전을 식별하고, 필요한 검증과 배포 후 정상 동작을 확인한다.
- 동시 배포와 부분 적용을 고려하고, 데이터 변경을 포함한 복구 방법을 확인한다.

## 5. 데이터 보호와 관측

- 볼륨, 데이터 경로와 데이터베이스 설정 변경은 기존 데이터의 유지 및 복구 가능성을 먼저 확인한다.
- 운영 데이터 삭제, 볼륨 초기화와 복구에 영향을 주는 정리는 정확한 대상과 영향을 설명하고 명시적인 승인 후 수행한다.
- 로그·메트릭 수집에는 필요한 서비스 식별 정보를 유지하고, 보관 기간과 저장 용량을 관리한다.
- 사용자·요청별 식별자처럼 값의 종류가 계속 늘어나는 정보는 메트릭이나 로그 스트림의 label로 무분별하게 추가하지 않는다.
- 수집 경로, 서비스 이름이나 포트를 변경하면 수집 설정과 조회 화면의 연결도 함께 확인한다.
- 관측 데이터의 민감 정보 노출과 관측 장애가 서비스 운영에 미치는 영향을 확인한다.

## 6. 변경 검증

- 실제 비밀값 없이 수행할 수 있는 설정·구문 검증을 먼저 실행한다.
- 구문 검증과 서비스 기동·연결 검증을 구분한다. 구문 검증 성공을 운영 동작 보장으로 간주하지 않는다.
- 로컬 검증은 운영 데이터와 분리된 환경에서 수행한다. 검증을 이유로 운영 배포나 데이터 초기화를 실행하지 않는다.
- 관련 설정, CI/CD와 애플리케이션 요구가 함께 맞는지 최종 변경 내용을 확인한다.
- 실행한 검증과 실행하지 못한 확인, 운영 적용 전 필요한 작업을 구분해 보고한다.
