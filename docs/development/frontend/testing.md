# 프론트엔드 테스트 지침

## 목적

이 문서는 iOS frontend의 테스트 작성과 검증 방식을 정하는 팀 검토용 초안이다.
테스트를 실행 가능한 명세로 다루는 공통 원칙은 Root `AGENTS.md`를 따른다.

## 1. 테스트 범위

- 단위 테스트는 앱 모델 변환, 입력 검증, 날짜·레이아웃 계산과 ViewModel 상태 전이를 검증한다.
- 통합 테스트는 Repository, `APIClient`, DTO 디코딩과 Service 변환 등 여러 경계가 함께 동작하는 경로를 검증한다.
- 네트워크 통합 테스트에는 실제 Backend 대신 `URLProtocol` 기반 응답을 사용할 수 있다. 실제 서버와의 검증은 별도로 구분한다.
- UI 테스트는 화면 표시, 사용자 입력과 navigation처럼 앱 실행이 필요한 사용자 흐름을 검증한다.
- View 생성과 콜백만 확인하는 테스트를 실제 렌더링이나 사용자 조작 검증으로 간주하지 않는다.

## 2. 작성 방식

- `CalioTests`의 모델·Service·ViewModel 테스트는 기존의 Swift Testing 형식을, `CalioUITests`는 XCTest 형식을 따른다.
- 테스트 이름은 조건과 기대 동작을 드러내고, 구현의 내부 호출 순서보다 결과와 계약을 검증한다.
- Repository 대역과 주입 가능한 `URLSession`, `Calendar`, `TimeZone` 등을 사용하여 외부 환경의 영향을 제한한다.
- 날짜와 현재 시각에 의존하는 테스트는 기준값과 시간대를 고정한다.
- 비동기 테스트는 완료 조건을 기다리고, 임의의 대기 시간으로 성공 여부를 판단하지 않는다.
- 공유하는 네트워크 대역 상태가 있다면 테스트 간 격리나 직렬 실행으로 간섭을 방지한다.
- 테스트를 위해 프로덕션 타입의 가시성을 불필요하게 넓히지 않는다.

## 3. 변경 시 확인

- API 소비 변경은 요청 method·경로·body·인증과 응답 필드·오류 코드의 해석을 검증한다.
- 상태 변경은 로딩, 빈 결과, 실패, 재시도와 성공을 검증하고, 필요한 경우 취소·오래된 응답·중복 요청도 확인한다.
- 날짜 처리 변경은 종일 경계, 시간대 차이와 날짜 이동을 검증한다.
- 기본 테스트와 Preview는 운영 서버, 실제 계정과 비밀값에 의존하지 않도록 구성한다.
- 빌드·테스트는 프로젝트의 Xcode scheme과 사용 가능한 iOS Simulator에서 수행하고, 실행하지 못한 검증은 이유와 함께 보고한다.
