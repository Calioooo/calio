# 후보 판단 예시

아래는 Calio와 무관한 가상 서비스의 사례다. 리뷰에서 판단이 모호할 때 관련 사례만 읽는다.

각 사례의 정책과 구조는 해당 예시에서만 가정한다. 프로젝트 규칙이나 필수 점검 목록으로 적용하지 않는다. 실제 판단은 프로젝트의 지침과 코드·계약에 근거한다. 예시는 지적의 정답보다 의심을 확인하거나 기각하는 과정을 보여준다.

## Backend: 제거된 검사와 남아 있는 보호 장치

- 가정: 도서관 서비스는 회원의 대출 한도 초과를 허용하지 않는다.
- 의심: 이번 변경에서 대출 요청 처리 코드의 한도 검사가 제거되었다.
- 확인: 실제 대출을 수행하는 메서드와 관련 진입점에 동일한 검증이 남아 있는지 확인한다. 테스트가 한도 초과 요청을 검증하는지도 읽는다.
- 보고: 한도에 도달한 회원이 변경된 경로로 추가 대출할 수 있으면 발생 조건과 대출 처리 위치를 제시한다.
- 기각: 해당 경로의 대출 처리 메서드가 한도 초과를 거절한다면 검사 삭제만으로 기능 오류를 지적하지 않는다.

## 설계: 실행 결과와 책임 규칙을 구분하기

- 가정: 가상 포인트 서비스의 문서가 잔액 차감 조건을 포인트 계정 객체에서 보호하도록 명시한다.
- 의심: 새 사용 경로가 객체 밖에서 잔액을 검사하고, 조건 없는 잔액 대입 메서드를 호출한다.
- 확인: 실제 변경 메서드, 적용 지침의 범위와 예외, 다른 변경 진입점을 확인한다. 메서드 이름만으로 내부 검증이 없다고 단정하지 않는다.
- 보고: 검증 없이 잔액을 대입하고 명시된 책임 규칙을 위반한다면 설계 문제로 보고한다. 현재 호출 경로에서 음수 잔액이 발생한다고 과장하지 않는다.
- 기각: 변경 메서드가 조건을 보호하거나 문서에서 해당 배치를 허용하면 이 책임 위반 후보를 기각한다. 가정과 같은 규칙이 없는 실제 프로젝트에 예시의 설계를 강요하지 않는다.

## Frontend: 오래된 검색 응답과 테스트의 검증 범위

- 가정: 상품 검색 화면은 마지막으로 입력한 검색어의 결과를 표시해야 한다.
- 의심: 검색 A 다음 B를 요청했는데 A의 응답이 늦게 도착해 B의 결과를 덮어쓸 수 있다.
- 확인: 응답 반영 전에 현재 요청인지 검사하는지 확인한다. 취소 호출의 존재만 보지 않고 늦은 결과가 반영되는 경로를 추적한다. 단일 요청 테스트의 통과는 순서 역전의 안전성을 입증하지 않는다.
- 보고: 오래된 응답이 반영될 수 있으면 요청·완료 순서와 잘못 표시되는 결과를 제시한다. 필요하면 완료 순서를 제어하는 가짜 응답으로 검증한다.
- 기각: 현재 요청의 응답만 반영하도록 보호되어 있다면 해당 후보를 기각한다.

## Backend·Frontend 계약: 내부 이름과 전송 값

- 가정: 배송 조회 API의 상태 문자열을 모바일 앱이 정해진 값으로 해석한다.
- 의심: 서버의 배송 상태 이름이 바뀌었는데 앱 코드에는 변경이 없다.
- 확인: 실제 직렬화 값, 해당 상태를 반환하는 경로, 앱의 디코딩과 미지원 값 처리를 확인한다.
- 보고: 정상 경로에서 새 값이 반환되고 소비자가 이를 처리하지 못한다면 응답 예시와 실패 위치를 제시한다.
- 기각: 내부 이름만 바뀌고 전송 값이 유지되거나 소비자가 계약에 맞게 처리하면 이름 변경만으로 호환성 문제를 지적하지 않는다.

## 변경 귀속: 코드 이동과 새 호출 경로

- 가정: 파일 보관 서비스의 크기 계산 메서드가 다른 파일로 이동했다.
- 의심: 빈 파일 목록에서 계산이 실패하는 코드가 diff에 나타난다.
- 확인: 이전 버전의 구현과 호출 조건을 비교한다. 이번 변경이 빈 목록을 전달하는 새 경로를 추가했는지 확인한다.
- 보고: 새 호출 경로가 실패 조건에 도달하게 했다면 그 경로를 도입한 변경을 근거로 보고한다.
- 기각: 구현과 호출 조건이 동일한 순수 이동이라면 기존 결함을 이번 변경이 도입한 문제로 세지 않는다.

## PR 범위: 명세의 일부만 구현하는 변경

- 가정: 사용자가 참조를 요청한 보고서 내보내기 명세를 PR 1의 저장 구조, PR 2의 생성 API, PR 3의 화면으로 나누기로 명시했다.
- 의심: PR 1에 생성 API와 화면이 없다.
- 확인: 사용자나 PR 설명이 정한 현재 범위를 확인한다. 전체 명세나 현재 diff만으로 완료 범위를 추정하지 않는다.
- 보고: PR 1이 기존 보고서 조회를 깨뜨린다면 현재 동작의 문제로 검토한다.
- 기각: 후속 PR로 지정된 API·화면의 부재는 지적하지 않는다. 현재 범위가 불명확하면 명세는 맥락으로만 사용하고 누락을 확정하지 않는다.
